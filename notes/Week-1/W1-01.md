## 3. Kiến thức

- **Solution và project:** project (`.csproj`) là một đơn vị build ra một file `.dll`/chương trình. Solution
  (`.slnx`) chỉ là danh sách các project để build/mở cùng lúc. `.slnx` là định dạng XML mới, ngắn và ít
  conflict khi merge hơn `.sln` cũ.
- **`Directory.Build.props`:** MSBuild (công cụ build của .NET) tự tìm file này ở thư mục cha và áp dụng cho mọi
  project bên dưới. Nhờ vậy cấu hình như `Nullable` chỉ viết **một lần**, không project nào "lỡ quên".
- **Nullable reference types:** trình biên dịch cảnh báo khi một biến có thể là `null` mà bạn dùng như không-null.
  Kết hợp `TreatWarningsAsErrors` → cảnh báo thành lỗi build → lỗi `NullReferenceException` bị chặn từ sớm.
- **Central Package Management (CPM):** phiên bản mọi NuGet package nằm trong `Directory.Packages.props`;
  `.csproj` chỉ ghi tên package. Không bao giờ có chuyện 2 project dùng 2 phiên bản khác nhau của cùng package.
- **`global.json`:** chọn phiên bản SDK cho thư mục này. `rollForward: latestFeature` = cho phép bản vá 10.0.x mới
  hơn nhưng **không** nhảy lên .NET 11 dù máy có cài.
- **xUnit v3 và Microsoft.Testing.Platform (MTP):** xUnit v3 biến mỗi project test thành một chương trình chạy được
  (`OutputType=Exe`) và dùng MTP — cách chạy test mới của .NET, thay cho VSTest cũ. Trên .NET 10 SDK, lệnh
  `dotnet test` chỉ chạy MTP khi được bật trong `global.json`.
- **Docker Compose:** mô tả các container cần chạy bằng một file YAML; `docker compose up -d` bật chúng ở chế độ nền.
  - **Named volume** (`postgres-data`): nơi Docker lưu dữ liệu database, tồn tại kể cả khi xóa container.
  - **Healthcheck** (`pg_isready`): Docker tự hỏi PostgreSQL "sẵn sàng chưa?" mỗi 5 giây → trạng thái `healthy`.
  - **Port mapping** `127.0.0.1:5434:5432`: cổng 5434 trên máy bạn → cổng 5432 trong container; `127.0.0.1` nghĩa
    là chỉ chính máy bạn kết nối được, máy khác trong mạng LAN thì không.
- **Biến môi trường và `.env`:** Compose đọc `.env` để điền `${POSTGRES_PASSWORD}`. Cú pháp `${VAR:?message}` bắt
  buộc biến phải có giá trị, nếu không thì dừng và in `message`. `${VAR:-5432}` = dùng `5432` khi biến trống.
- **Line endings (LF/CRLF):** Linux dùng `\n` (LF), Windows dùng `\r\n` (CRLF). `.gitattributes` với
  `eol=lf` khiến git luôn lưu LF. Ví dụ thật trong task: 2 file `appsettings` do template tạo có CRLF, git tự chuyển
  sang LF khi commit.
- **BOM UTF-8:** 3 byte ẩn (`EF BB BF`) ở đầu một số file do công cụ Windows tạo ra. Vô hại nhưng không cần thiết,
  đã bỏ đi cho thống nhất.

## 4. Quyết định và lý do

| Quyết định | Phương án khác | Vì sao chọn |
|---|---|---|
| `.slnx` | `.sln` cũ | Mặc định của .NET 10, dễ đọc, ít conflict |
| Tên file project = tên thư mục (`Api.csproj`), namespace `Gearnix.Api` | Namespace `Api` | Khớp `Rule.md` §2 và lệnh `--project src/Api`; namespace có tiền tố sản phẩm thì rõ nghĩa hơn |
| Không bật analyzer nâng cao | `AnalysisLevel latest-recommended` | Warning = lỗi, nên analyzer nghiêm sẽ chặn build vì lỗi style; thêm sau dễ |
| Central Package Management | Ghi phiên bản trong từng `.csproj` | Một nguồn phiên bản duy nhất; Dependabot (W1-02) hỗ trợ |
| `postgres:17` | `postgres:18` | Đủ tính năng (`pg_trgm`), nhiều tài liệu; image 18 đổi đường dẫn dữ liệu, dễ nhầm khi gắn volume |
| Mật khẩu trong `.env` (gitignore) + `.env.example` | Ghi thẳng mật khẩu trong compose | Không bao giờ commit secret, kể cả mật khẩu dev |
| Cổng ngoài lấy từ `POSTGRES_PORT` (máy này dùng 5434) | Cố định 5432 | Dự án khác trên máy đã dùng 5432/5433; mặc định vẫn 5432 cho người khác; deploy và Testcontainers không bị ảnh hưởng |
| W1-01 **không có test** (ngoại lệ có ghi rõ) | Test "app khởi động được" | Chưa có hành vi nào để test; test đó cần thêm package chưa được duyệt. Test đầu tiên ở W1-03 (`/health`) |
| Bỏ OpenAPI, HTTPS redirect, `UseAuthorization` của template | Giữ nguyên template | Mỗi thứ thuộc một task sau (W1-04, W5-03, W1-05); thêm đúng lúc thì giải thích được |

## 5. Test

Task này **chưa có test tự động** (xem bảng trên). Thay vào đó đã **chạy thật** các bước kiểm chứng:

| Kiểm chứng | Kết quả | Chứng minh điều gì |
|---|---|---|
| `dotnet build` | 0 warning, 0 lỗi | Cấu hình chung đúng; nullable + warning-as-error đang bật mà code vẫn sạch |
| `dotnet test` | Nhận ra 2 project, 0 test, **mã thoát 8** | Cấu trúc test sẵn sàng. Mã 8 = MTP báo "không có test nào chạy" (cố ý coi là lỗi để phát hiện test bị bỏ sót) |
| `dotnet format --verify-no-changes` | Mã thoát 0 | Code đúng quy tắc `.editorconfig` |
| `docker compose config` khi thiếu `.env` / mật khẩu trống | Báo lỗi rõ biến nào thiếu | Không thể vô tình chạy database không mật khẩu |
| `docker compose up -d` | Container `healthy` ở `127.0.0.1:5434` | Database chạy được, song song với dự án khác |
| Truy vấn trong container | User/DB `gearnix`, PostgreSQL 17.12, `pg_trgm` có sẵn | Đúng phiên bản; extension cho tìm kiếm (W4-05) dùng được |
| `dotnet run --project src/Api` + `GET /` | Nghe ở `:5296`, trả `404` | API khởi động; 404 là đúng vì chưa có endpoint |

## 6. Câu hỏi phỏng vấn

1. **"`Directory.Build.props` dùng để làm gì?"**
   → Cấu hình chung cho mọi project bên dưới thư mục, MSBuild tự nạp. Tránh lặp và tránh một project quên bật
   `Nullable`/`TreatWarningsAsErrors`.
2. **"Vì sao không commit mật khẩu database, dù chỉ là môi trường dev?"**
   → Repo public thì ai cũng đọc được; thói quen ghi secret vào file commit sẽ có ngày lộ secret thật. Dùng `.env`
   gitignore + `.env.example` để người khác biết cần điền gì. Compose dừng ngay nếu thiếu (`${VAR:?}`).
3. **"Port mapping `127.0.0.1:5434:5432` nghĩa là gì? Đổi cổng có ảnh hưởng production không?"**
   → Cổng 5434 trên máy → 5432 trong container, chỉ nhận kết nối từ chính máy. Production không bị ảnh hưởng: ở đó
   API và database đều là container, nói chuyện qua mạng nội bộ Docker bằng tên dịch vụ, thường không mở cổng ra ngoài.

## 7. Lưu ý

- **`dotnet test` trả mã 8 khi chưa có test** → CI ở W1-02 sẽ đỏ cho tới khi W1-03 thêm test. Quyết định cách xử lý
  khi grill W1-02 (ví dụ tạm bỏ qua mã 8 chỉ trong CI, **không** tắt trong cấu hình chung).
- `ss` trong WSL **không thấy** cổng do Docker Desktop mở → muốn biết cổng nào đang bị dùng, xem `docker ps`.
- Template `.editorconfig` cấm dòng trống cuối file C# — đã đổi thành bắt buộc, cho khớp với git.
- `restart: unless-stopped`: container tự chạy lại khi Docker khởi động, trừ khi bạn chủ động `docker compose stop`.
